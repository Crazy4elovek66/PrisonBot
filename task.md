## 1. ЦЕЛЬ И БИЗНЕС-ТРЕБОВАНИЯ

Устранить 3 критических недоработки, подтвержденных на живом интерфейсе:

1. **Вкладка Боссы -> Рукопашные удары (Авто-режим и раздельные таймеры)**:
   - Положение ползунка `Авто` теперь сохраняется, однако после его включения автоматические рукопашные удары (`В грудь`, `В пах`, `В глаз`, `Коленом`) все равно не наносятся.
   - У каждого из 4 рукопашных ударов в игре свой **индивидуальный** таймер перезарядки (не один общий на все удары).
   - При включенном `Авто` бот обязан гарантированно и немедленно наносить **все готовые (не на КД)** рукопашные удары: сразу в момент включения тумблера (если бой уже идет), сразу при старте нового боя и далее по истечении индивидуального таймера каждого конкретного удара на протяжении всего боя.
2. **Вкладка Тату и шмот -> Примерочная (Глаза поверх головных уборов)**:
   - Несмотря на добавление верхнего canvas-слоя в прошлой итерации, у комплектов одежды (`Мафия`[cite: 31], `Комплект "Кельвин Кляйн"`[cite: 32] и других сетов с головными уборами) глаза персонажа по-прежнему отрисовываются поверх полей шляпы и козырька кепки[cite: 31, 32].
   - Необходимо найти реальную причину перекрытия в DOM/Canvas/картах зон и исправить z-order так, чтобы головные уборы, маски, шлемы, капюшоны и очки гарантированно перекрывали глаза (и никогда наоборот).
3. **Вкладка Уведомления -> Конкретное название выпавшей нычки**:
   - В уведомлениях по ходкам (например, `Ходки: КРЕСТЫ`, `Кликов: 1`) вместо реального названия выпавшей нычки до сих пор выводится заглушка `🎁 Коллекционный предмет (Предмет коллекции)`[cite: 33].
   - Необходимо довести до рабочего состояния резолвинг и отображение конкретного названия выпавшей нычки (и при наличии - ее коллекции и иконки), исключив fallback в безымянный `Коллекционный предмет` для всех известных игровых нычек.

## 3. ЛОГИКА / АРХИТЕКТУРА

### 3.1. Боссы - диагностика и починка авто-рукопашки с индивидуальными таймерами
- **Обязательная диагностика**:
  - Проверить логику в `web/routes.py` при сохранении `boss_auto_melee = true`: вызывается ли немедленно `boss_worker.trigger_auto_melee()` (или аналогичный триггер), когда пользователь включает ползунок во время уже идущего боя?
  - Проверить в `workers/boss_worker.py` и `client/api/boss.py`, какие именно поля статуса боя и таймеров рукопашных ударов приходят от игрового API (сверить через MCP DevTools в живой игре). Проверить, не отбрасываются ли удары из-за:
    - неверной проверки активного боя (например, проверка только локального флага воркера вместо реального активного боя на сервере);
    - чтения одного общего таймера/флага вместо 4 независимых `cooldown` / `ready_at` по каждому ID удара;
    - неверных ID или эндпоинта ударов (`punchChest`, `kickBalls`, `pokeEyes`, `kneeEar` - проверить точные имена/коды в `client/api/boss.py` и `parsed_js/bundle.js`);
    - тихого проглатывания исключений или блокировки общим `asyncio.Lock` во время активного боя.
- **Целевая архитектура `execute_ready_melee_hits()`**:
  - Вести независимую карту кулдаунов для всех 4 рукопашных ударов:
    ```python
    # Пример структуры индивидуальных таймеров
    melee_ready_at: dict[str, float] = {
        "punchChest": 0.0,
        "kickBalls": 0.0,
        "pokeEyes": 0.0,
        "kneeEar": 0.0,
    }
    ```
  - В методе `execute_ready_melee_hits()` при `boss_auto_melee == True`:
    1. Получить актуальное состояние боя с боссом (если бой не активен или босс уже мертв `hp <= 0` - ничего не бить, вернуть `None`).
    2. Синхронизировать индивидуальные таймеры всех 4 ударов из ответа игрового API.
    3. Пройти циклом по всем 4 ударам **независимо**: для каждого удара, у которого индивидуальный таймер `<= 0` (готов), выполнить атаку с короткой паузой `0.3-0.5s` и обновить его персональный `ready_at` из ответа сервера. Ошибка или КД одного удара не должна прерывать выполнение остальных готовых ударов.
    4. После цикла вычислить `next_wakeup = min(t for t in melee_ready_at.values() if t > now)` и перепланировать одноразовую задачу в `core/scheduler.py` (`reschedule_boss_melee_in(delay)`) ровно на `max(1.0, next_wakeup - now + 0.5)`.
    5. Обновить индивидуальные таймеры в `StateHub` и вернуть их в UI, чтобы таймер каждой кнопки на фронтенде соответствовал реальному КД в игре.
  - Точки немедленного триггера:
    1. Переключение `boss_auto_melee` в `True` через `POST /api/settings` (или `/api/config`) -> немедленно запускает `execute_ready_melee_hits()` в фоне.
    2. Старт любого боя (автоатака, пресет, ручная атака через UI) -> немедленно запускает `execute_ready_melee_hits()`.
    3. Планировщик (`core/scheduler.py`) -> пробуждается точно к ближайшему индивидуальному откату и имеет страховочный тик раз в 20-30 секунд, пока активен бой.
  - Добавить подробное логирование (`logger.info` / `logger.warning`) на каждый шаг цикла авто-рукопашки (какой удар готов, какой на КД и сколько секунд осталось, результат запроса), чтобы в логах `prisonbot.service` было прозрачно видно работу механики.

### 3.2. Тату и шмот - окончательное исправление перекрытия головных уборов глазами
- **Обязательная диагностика через MCP DevTools и анализ кода**:
  - Не гадать вслепую - открыть примерочную в локальном веб-интерфейсе на сетах `Мафия` и `Комплект "Кельвин Кляйн"`, инспектировать реальный DOM, CSS `z-index`, размеры и содержимое всех `<canvas>` элементов (`fittingRoomStaticCanvas`, `fittingRoomAnimLayers`, `fittingRoomTopStaticCanvas` и т.д.).

    1. Какие реальные `zone` / `slot` / `type` / `layer` / `zIndex` имеют шапки/шляпы/кепки (в частности, шляпа из `Мафии` и кепка из `Кельвин Кляйн`). На скриншотах[cite: 31, 32] видно, что шляпа и кепка рисуются *ниже* анимированного/статичного слоя глаз - значит либо их `zone` не попадает в `[4, 3, 8]`, либо `fittingRoomTopStaticCanvas` в HTML/CSS находится ниже `fittingRoomAnimLayers`, либо глаза рисуются на том же верхнем слое / поверх всех canvas!
    2. Проверить точный порядок слоев оригинальной игры в `parsed_js/bundle.js` (как игра сортирует `EyesAnim`, `Head`, `Hat`, `Mask`, `Glasses`, `Beard`, `Hair` и все остальные зоны одежды).
- **Исправление рендера в `web/static/app.js`, `web/static/index.html`, `web/static/styles.css`**:
  - Выстроить строго детерминированную стопку слоев в DOM и CSS (явно задать `z-index` для каждого слоя контейнера примерочной):
    - `z-index: 1` - фон камеры (статичный или Spine-комната);
    - `z-index: 2` - базовое тело персонажа + татуировки тела/лица + нижние слои одежды (ниже лица/глаз);
    - `z-index: 3` - анимация лица и глаз (`EyesAnim` / `MouthAnim` и др.);
    - `z-index: 4` - верхний статичный слой одежды (`fittingRoomTopStaticCanvas`) и/или верхние анимированные слои одежды, содержащий **все** головные уборы (шляпы, кепки, шапки, шлемы, капюшоны, короны), маски, очки и элементы, перекрывающие область лица/глаз.
  - Определять принадлежность предмета к верхнему слою надежно - по точному маппингу игровых зон/слотов из `parsed_js/bundle.js` (а не по неполному списку из 3 чисел). Если у предмета есть собственный `zIndex` / `order` из игровых метаданных - ориентироваться напрямую на сравнение с `zIndex` слоя `EyesAnim`.
  - Убедиться, что при переключении комплектов и сбросе примерки `fittingRoomTopStaticCanvas` корректно очищается (`clearRect`) вместе с основным canvas, чтобы старые шляпы не залипали на экране.
  - **Обязательная визуальная проверка**: открыть через MCP DevTools примерочную с сетами `Мафия`, `Комплект "Кельвин Кляйн"` и еще 2-3 сетами с головными уборами/масками и убедиться по реальному рендеру (скриншоту), что глаза полностью скрыты под полями шляпы и козырьком кепки.
