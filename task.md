# ТЕХНИЧЕСКОЕ ЗАДАНИЕ: ИССЛЕДОВАНИЕ И ПАРСИНГ ПОЛНОГО КАЛЕНДАРЯ МЕСЯЧНЫХ ДЕЛЮГ («ОТ ЗВОНКА ДО ЗВОНКА») И ВСЕХ НАГРАД МЕСЯЦА + АККОРДЕОН В UI + ДЕПЛОЙ НА VPS

Ты выступаешь в роли Senior Full-Stack разработчика (Python / FastAPI / Asyncio / SQLite + Vanilla JS / HTML / CSS) и реверс-инженера игровых API-контрактов на проекте PrisonBot.

**Текущее состояние проекта и доступные источники правды:**
- В проекте реализованы серверная синхронизация времени (`v20261127_09` / `prisonbot-assets-v30`) и парсинг общаков у заявок в друзья (`v20261127_10` / `prisonbot-assets-v31`). Все 293 теста проходят, прод работает на VPS `178.17.60.16:/opt/prisonbot` (`prisonbot.service`).
- Сейчас блок «Месячные делюги» отображает только актуальное задание на текущий день: невозможно посмотреть, какое задание было вчера (например, `27.11`) и какие задания запланированы на последующие дни месяца (`29.11`, `30.11` и т.д.), а также не расписаны в полном объеме все этапные награды месяца и пороги их получения.
- Для точного реверс-инжиниринга в твоем распоряжении:

  2. Исходники клиента игры: `parsed_js/bundle.js`, `parsed_js/cdn.js`, `raw_dump/network_log.json`, `docs/daily_actions_contracts.md`, `docs/api_map.md`.

Твоя задача - провести точный аудит возможности получения расписания месячных делюг заранее на весь месяц, реализовать максимально полный парсинг календаря делюг по датам и всех этапных наград месяца с сохранением истории в БД, добавить аккуратный аккордеон с мини-таблицей `Дата | Суточное задание` и блоком наград в блок «Месячные делюги» в стилистике системы, покрыть все тестами и выгрузить релиз на VPS с живой проверкой.

## 1. ЦЕЛЬ И БИЗНЕС-ТРЕБОВАНИЯ

### 1.1. Главная фича - расписание месячных делюг по датам на весь месяц
- Проверить через MCP DevTools (`localhost:9222`), живой игровой API и `parsed_js/bundle.js`, отдает ли игровой сервер (или клиентский конфиг/CDN) список заданий сразу на весь месяц вперед (или с разбивкой по дням `1..30/31`).
- Возможны два технических исхода исследования - обработать их строго честно и максимально полезно для пользователя:
  - **Сценарий A (Сервер / клиентский конфиг отдает задания на весь месяц или будущие даты):**
    - реализовать полный парсинг всех заданий на каждый день месяца сразу в начале месяца (и при обновлении состояния), сопоставить каждый день с конкретной календарной датой (`DD.MM`, например `01.11` .. `30.11`), текстом задания, целью/прогрессом и статусом дня (`completed`, `missed`, `today`, `upcoming`);
    - сохранить распарсенный план месяца в SQLite (`core/database.py`), чтобы он был мгновенно доступен и не терял формулировки прошедших дней.
  - **Сценарий B (Игровой сервер скрывает тексты будущих заданий до наступления дня и ни один эндпоинт/ассет их не содержит):**
    - строго зафиксировать в отчете доказательство (сырой JSON-ответ игрового API + релевантный фрагмент `parsed_js/bundle.js` + проверенные эндпоинты);
    - все равно реализовать полную календарную таблицу всех дней месяца (`01.MM` .. `30/31.MM`) со статусами каждого дня из API (`Выполнено`, `Пропущено`, `Сегодня`, `Ожидается`) и **накопительное сохранение суточных заданий в SQLite**, чтобы все пройденные дни месяца (включая вчерашний) сохранялись с текстом задания, а для закрытых сервером будущих дней честно отображался статус `Откроется DD.MM` (без фейков и выдуманных заданий).

### 1.2. Полный парсинг всех наград за месяц и порогов получения
- Парсить из игрового API **все этапные награды месяца** (на скриншоте окна «От звонка до звонка» видно 5 наград справа с порогами вида `Выполни 10 делюг`, `Выполни 20 делюг`, `Выполни 30 делюг` и уже выполненные первые этапы):
  - для каждой награды извлечь: индекс/ID этапа, требуемое количество выполненных делюг (`required_count`), текущее количество выполненных делюг (`completed_count`), состав награды (название ресурса/предмета, количество `x30`, `x2`, `x70`, `x4`, `x1`, стоковую иконку из игры/CDN), статус (`claimed` / `claimable` / `locked`);
  - если у награды статус `claimable` (порог достигнут, но еще не забрана) - дать возможность забрать ее прямо из блока (или через существующий эндпоинт сбора месячной награды, сверив контракт с `reference_archive/pro_prison_bot/api_snapshots/__next__api_game_monthly_claim.txt`).

### 1.3. UI в блоке «Месячные делюги»
- Внутри существующего блока «Месячные делюги» в интерфейсе бота:
  - оставить компактную верхнюю сводку: текущий прогресс месяца (`Выполнено X/30`), прогресс-бар и актуальное задание на сегодня (или статус «Делюги кончились / Все выполнено на сегодня»);
  - добавить компактный блок **всех этапных наград месяца** с их оригинальными иконками, количеством (`x30`, `x70` и т.д.), порогом (`N делюг` / `X/N`) и понятным визуальным статусом (`Получено`, `Забрать`, `Осталось K`);
  - добавить стильный **аккордеон** (в единой темной стилистике системы, по умолчанию свернутый, чтобы не раздувать главный экран), при раскрытии которого отображается аккуратная мини-таблица:
    - колонки: `Дата` | `Суточное задание` (плюс компактный индикатор статуса дня: выполнено / пропущено / сегодня / запланировано);
    - текущая дата визуально подсвечена (бейдж «Сегодня»), выполненные и пропущенные дни аккуратно различаются по цвету/иконке;
    - состояние раскрытия аккордеона НЕ должно сбрасываться при SSE-обновлениях (`domain_sync` / `snapshot`) и поллинге.
