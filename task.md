Ты выступаешь в роли Senior Full-Stack разработчика (Python / FastAPI / Asyncio / SQLite + Vanilla JS / HTML / CSS) и реверс-инженера игровых механик на проекте PrisonBot.

**Анализ текущего состояния проекта и выявленные проблемы:**

  3. **Отсутствие взаимоисключения целей энергии (ходки/бунт vs мастера)**:
     - Сейчас можно одновременно включить авто-прохождение ходок/бунтов и авто-тренировку у мастеров, из-за чего воркеры/логика могут конфликтовать за один и тот же пул энергии.

## 1. ЦЕЛЬ И БИЗНЕС-ТРЕБОВАНИЯ

### 1.1. Гарантированное и точное отображение затрат энергии для полной ходки, бунта и обучения у мастера
- Провести аудит через `parsed_js/bundle.js`, живой API (`localhost:9222` и VPS) и `reference_archive/pro_prison_bot/`, чтобы выяснить точные формулы/конфиги стоимости энергии:
  - для **полной ходки (День)** по каждой из 15 тюрем игры;
  - для **полного бунта (Ночь)** по каждой из 15 тюрем игры;
  - для **полного года/круга обучения у каждого из 16 мастеров** (с учетом текущего уровня мастера `ур. N` и, если применимо, разницы между стоимостью полного круга и остатком энергии до завершения текущего круга).
- Устранить первопричину пропадания цифр (`Ночь: -` у `В.ЦЕНТРАЛ`, отсутствие строки у `КРЕСТЫ`, отсутствие `круг: NNN эн.` у мастеров 2..16 и исчезновение `443 эн.` у `ПЕТЯ ВЕРСТАК` после SSE/повторного рендера):
  - значения затрат энергии должны присутствовать **всегда и гарантированно** при первой загрузке, после переключения вкладок, после ручных действий и после любых SSE-обновлений (`snapshot` / `domain_sync`), одинаково стабильно на десктопе и мобильных устройствах;
  - ни у одной открытой тюрьмы не должно быть прочерка `-` или пропавшей строки `⚡ День: X / Ночь: Y` (а для закрытых тюрем, если известна базовая стоимость из конфига игры, показывать ее либо аккуратно подписывать условие открытия + стоимость);
  - у **каждого** из 16 мастеров должна гарантированно отображаться точная стоимость полного круга обучения `⚡ Полный круг: NNN эн.` (и стоимость 1 шага/действия, если доступна в API/конфиге).

### 1.2. Приведение блока «Тренировки у мастеров» к единому стилю с «Ходками»
- Переработать раздел «Тренировки у мастеров» в единой визуальной архитектуре с разделом «Ходки и бунты»:
  - **Верхняя карточка выбранного мастера** (аналогично карточке выбранной тюрьмы):
    - название активного мастера, его текущий уровень (`ур. N`), прогресс текущего круга/года обучения (прогресс-бар `шаг X / Y`, `%` и остаток энергии до закрытия круга, если доступен);
    - переключатель `Авто` (авто-тренировка у выбранного мастера) в шапке справа - в том же стиле, что и тумблер `Авто` у ходок;
    - кнопки ручного действия: `Тренироваться (⚡ X)` (1 шаг) и `⚡ Слить всю энергию` (в выбранного мастера, если поддерживается существующим API или добавить безопасный цикл/эндпоинт по аналогии с ходками).
  - **Сетка «Все мастера игры»** (аналогично сетке «Все тюрьмы игры»):
    - адаптивная сетка интерактивных карточек для всех 16 мастеров (`ПЕТЯ ВЕРСТАК`, `ЯША В ПОЛЕДЫМ`, ..., `ПАША КАРЛО`);
    - в каждой карточке: название мастера, статус открыт/закрыт (иконка замка), текущий уровень (`ур. N`) и/или прогресс, и гарантированная строка затрат энергии золотым акцентом `⚡ Полный круг: NNN` (плюс шаг, если уместно);
    - выбранный целевой мастер подсвечен золотой рамкой, клик по любой открытой карточке мастера сразу выбирает его как цель (и сохраняет в конфиг).
  - Сохранить идеальную адаптивность под десктоп и узкие мобильные экраны (`360px+`, как на мобильном скриншоте iOS).

### 1.3. Умное взаимоисключение целей энергии (только один активный авто-таргет)
- В системе должен быть активен **максимум один** автоматический потребитель энергии: либо **Ходки/Бунт**, либо **Обучение у мастера** (либо оба выключены).
- **Поведение в UI и на Backend:**
  - при включении тумблера `Авто` у мастеров -> тумблер `Авто` у ходок/бунтов **автоматически выключается**;
  - при включении тумблера `Авто` у ходок/бунтов -> тумблер `Авто` у мастеров **автоматически выключается**;
  - правило должно быть обеспечено **на всех трех уровнях**:
    1. **Backend API (`web/routes.py`) и БД (`core/database.py`)**: атомарное сохранение взаимоисключающих флагов при любом запросе на изменение настроек/тумблеров + немедленная публикация обновленного конфига в `StateHub` / SSE.
    2. **Воркер (`workers/prison_worker.py`)**: защитная проверка инварианта - если в унаследованной БД вдруг оказались включены оба флага, воркер не тратит энергию на обе цели одновременно и приводит состояние к валидному одному таргету.
    3. **Frontend (`web/static/app.js`)**: мгновенное синхронное переключение противоположного тумблера при клике, понятное всплывающее уведомление (toast) вроде `Авто-ходки отключены: выбран режим обучения у мастера` (и обратно), плюс полная синхронизация через SSE между вкладками и устройствами (ноутбук + телефон).
