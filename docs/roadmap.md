# ROADMAP: АВТОНОМНЫЙ BOT-CLIENT ДЛЯ TELEGRAM MINI APP (OLD PRISON / ТЮРЯГА V3)

Настоящий документ определяет архитектуру, стек технологий, этапы реализации и эксплуатационные требования для создания полностью автономного, масштабируемого Python-воркера, работающего без графического браузера напрямую через REST API игры.

---

## 1. АРХИТЕКТУРНОЕ ВИДЕНИЕ И СТЕК ТЕХНОЛОГИЙ

### 1.1. Ключевые требования к автономности
1. **Headless Zero-Browser:** Полный отказ от Selenium/Playwright в рантайме. Вся работа выполняется через HTTP-запросы с минимальным потреблением CPU и RAM (< 50 МБ на поток).
2. **Self-Healing Auth:** При истечении срока действия JWT (`401 Unauthorized`) бот автоматически обновляет пару токенов через Refresh Token либо самостоятельно генерирует новый `initData` через Telegram API.
3. **Multi-Account Support:** Возможность параллельного ведения нескольких игровых аккаунтов с привязкой каждого к персональному SOCKS5/HTTP прокси.
4. **Anti-Detect & Human-Behavior:** Рандомизация таймингов, имитация задержек между кликами по нормальному закону распределения, эмуляция мобильных заголовков Android/Chrome.

### 1.2. Технологический стек
- **Язык разработки:** Python 3.11+
- **Асинхронность:** `asyncio`
- **HTTP / Сеть:** `httpx` (HTTP/2, Connection Pooling, Client Timeouts, проксирование)
- **Telegram Client:** `Telethon` (для headless-авторизации в Telegram и вызова `messages.RequestWebViewRequest` для извлечения свежего `initData`)
- **База данных:** `aiosqlite` + `SQLAlchemy 2.0` (асинхронный ORM, миграции через `Alembic`)
- **Планировщик задач:** `APScheduler` (AsyncIOScheduler) с поддержкой Cron, Interval и dynamic jitter
- **Конфигурация:** `pydantic-settings` (.env, валидация типов)
- **Интерфейс управления и алертов:** Telegram-бот на `aiogram 3.x` (уведомления владельцу о дропах, боссах, ошибках)

## 3. ПОЭТАПНЫЙ ПЛАН РАЗРАБОТКИ (ROADMAP)

### 📌 ФАЗА 1: ЯДРО, АВТОРИЗАЦИЯ И РУТИННЫЙ ВОРКЕР (MVP)
> **Цель:** Получить рабочий каркас приложения, способный в автономном режиме поддерживать сессию и выполнять ежедневный сбор бесплатных наград.

- [ ] **Спринт 1.1: Слой хранения данных и конфигурации**
  - Описать модели `Account` (id, telegram_phone, proxy, is_active), `SessionData` (access_token, refresh_token, access_exp, init_data), `PlayerSnapshot` (userId, nickname, level, biceps, authority, soap, paper, energy).
  - Настроить асинхронный пул подключений SQLite.
- [ ] **Спринт 1.2: Headless Telegram Session & InitData Extractor**
  - Реализовать `TelethonSessionManager`: авторизация по номеру/tdata.
  - Метод получения свежего `initData`:
    ```python
    web_view = await client(functions.messages.RequestWebViewRequest(
        peer='oldprison_bot',
        bot='oldprison_bot',
        platform='android',
        from_bot_menu=False,
        url='https://oldprison-prod.luckygem.online/'
    ))
    # Извлечение tgWebAppData из web_view.url
    ```
- [ ] **Спринт 1.3: Клиент аутентификации (`AuthProvider`)**
  - Реализация `POST /api/auth/login` с передачей `initData` и эмуляцией Android-заголовков.
  - Реализация `POST /api/auth/refresh` для бесшовного обновления JWT по истечении `accessExp`.
  - Автоматический fallback: если `refresh` вернул 401 — инициировать получение нового `initData` через Telethon.
- [ ] **Спринт 1.4: MVP Routine Worker**
  - Автоматический сбор туалетной бумаги (`POST /api/daily/toilet-paper`).
  - Проверка и бритье бороды по таймеру (`POST /api/beard/update`).
  - Сбор накоплений с бизнесов (`POST /api/player/business/collect`).
  - Сбор всех подогревов от корешей (`POST /api/podogrev/collect/all`).
  - Вызов первичной синхронизации (`POST /api/player/init`) с записью статистики в БД.

### 📌 ФАЗА 2: БОЕВОЙ МОДУЛЬ И АВТО-УДАРЫ ПО БОССАМ
> **Цель:** Максимизация нанесения урона по боссам с нулевыми финансовыми затратами (откаты бесплатных ударов) и мониторинг боевого прогресса.

- [ ] **Спринт 2.1: Анализ боевого состояния**
  - Реализация методов `GET /api/boss/bootstrap` и `GET /api/boss/weapons`.
  - Извлечение ID текущего босса, оставшегося HP, лимита времени боя и кулдаунов рукопашных ударов.
- [ ] **Спринт 2.2: Ротация бесплатных ударов**
  - Расчет готовности каждого удара на основе временных меток сервера:
    - *Удар в грудь:* `lastPunchChestTime` + cooldown;
    - *Удар по яйцам:* `lastKickBallsTime` + cooldown;
    - *Удар в глаза:* `lastPokeEyesTime` + cooldown;
    - *Удар в ухо:* `lastKneeEarTime` + cooldown.
  - Выполнение комбо-атак без траты мыла и туалетной бумаги.
- [ ] **Спринт 2.3: Социальный урон и баффы**
  - Сбор накопленного урона от друзей (`GET /api/boss/friend-damage`).
  - Активация доступных гильдейских и личных баффов (`POST /api/boss-buffs/activate`).
  - Опциональная стратегия применения платного оружия (яды, самопалы, заточки) только при низком HP босса (< 5%) для добивания.

### 📌 ФАЗА 3: ТЮРЬМЫ, ЭНЕРГИЯ, ХОДКИ И МАСТЕРА
> **Цель:** Автоматический слив регенерируемой энергии в прокачку авторитета, сбор предметов и прохождение сюжетных зон.

- [ ] **Спринт 3.1: Менеджер энергии**

  - Опциональное использование чифира (`POST /api/player/energy/use-chefir`) при наличии в инвентаре.
- [ ] **Спринт 3.2: Авто-ходки по тюрьмам**
  - Загрузка списка доступных тюрем (`GET /api/prisons/all`).
  - Получение состояния активной тюрьмы (`GET /api/player/prison/:id`).
  - Прохождение дневных/ночных заданий (`POST /api/player/prison/:id/work?isDay=true/false`).
  - Активация пройденных чекпоинтов (`POST /api/player/prison/:id/checkpoints`).
- [ ] **Спринт 3.3: Работа у мастеров**

  - Выполнение заказов мастеров для прокачки бицухи (`POST /api/player/masters/:id/work`).

### 📌 ФАЗА 5: АНТИ-ДЕТЕКТ, БЕЗОПАСНОСТЬ И МОНИТОРИНГ
> **Цель:** Исключение банов игрового профиля, скрытность сетевого профиля и удобное управление с мобильного устройства.

- [ ] **Спринт 5.1: TLS & HTTP Fingerprinting**
  - Эмуляция TLS-отпечатка Chrome/Android (JA3/JA4) через связку с `curl-cffi` или кастомный SSLContext в `httpx`.
  - Генерация реалистичного набора клиентских заголовков:
    ```http
    User-Agent: Mozilla/5.0 (Linux; Android 14; SM-S918B) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/130.0.0.0 Mobile Safari/537.36
    X-Platform: android
    X-Language: ru
    X-Country: RU
    Origin: https://oldprison-prod.luckygem.online
    Referer: https://oldprison-prod.luckygem.online/
    ```
- [ ] **Спринт 5.2: Рандомизация интервалов (Jitter)**
  - Все таймеры планировщика запускаются с гауссовым разбросом: `delay = base_interval + random.gauss(0, jitter_std)`.
  - Имитация сна игрока (приостановка активности с 02:00 до 07:00 по времени часового пояса аккаунта).
- [ ] **Спринт 5.3: Мониторинг-бот (Telegram UI)**
  - Развертывание бота на `aiogram 3`:
    - Команда `/status` — вывод карточки профиля (баланс, урон по боссу, текущая энергия);
    - Команда `/pause` и `/resume` — мгновенная остановка воркеров;
    - Алерты в личку: обнаружение блокировки аккаунта, критические ошибки API, появление редких ивентов.
- [ ] **Спринт 5.4: CI/CD и Docker**
  - Подготовка легковесного `Dockerfile` (Alpine/Debian-slim).
  - Сборка `docker-compose.yml` с volume для базы данных и сессий.

## 4. МАТРИЦА РИСКОВ И СПОСОБЫ МИТИГАЦИИ

| Риск | Вероятность | Влияние | Способ минимизации |
| :--- | :--- | :--- | :--- |
| **Инвалидация сессионных токенов** | Высокая | Среднее | Двухуровневый `AuthProvider`: автоматический `/api/auth/refresh`, при отказе — перезапуск через `Telethon`. |
| **Блокировка аккаунта (Anti-Cheat)** | Средняя | Критическое | Полный отказ от чит-эндпоинтов (`/api/cheat/*`), строгое соблюдение кулдаунов ударов сервера, использование резидентных мобильных прокси. |
| **Смена структуры API при обновлениях игры** | Низкая | Высокое | Наличие скрипта `scripts/parse_dump.py` в репозитории: при апдейте JS-бандла запускается быстрый повторный анализ и генерация обновленного `api_map.md`. |
| **Капча / Cloudflare** | Низкая | Высокое | Игра размещена на выделенном Nginx сервере без Cloudflare Challenge; при появлении капчи отправлять скриншот/уведомление в Telegram-бота владельца. |

## 5. ОЖИДАЕМЫЙ РЕЗУЛЬТАТ

После завершения Фаз 1–3 владелец бота получает полностью автономную систему, которая:
1. Занимает < 50 МБ ОЗУ на сервере.
2. Круглосуточно фармит туалетную бумагу, подогревы, бизнес и боссов.
3. Не требует ручного ввода токенов или открытия браузера.
4. Отправляет регулярные сводки прогресса в Telegram.
