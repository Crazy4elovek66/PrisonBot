# ТЕХНИЧЕСКОЕ ЗАДАНИЕ: ДОРАБОТКА WEBAPP-КЛИЕНТА, ГИБКИЕ ФИЛЬТРЫ ДРУЗЕЙ, РЕАЛЬНЫЕ БИЗНЕСЫ И ПОЛНЫЕ ХУКИ ИГРЫ

Ты выступаешь в роли Senior Full-Stack Python & Frontend разработчика. Твоя задача - устранить выявленные недочеты в `PrisonBot`, оптимизировать сетевую задержку (пинг), исправить расчет уровней и прибыли бизнесов, реализовать гибкую систему приема заявок в друзья с фильтрами по характеристикам, добавить главный выключатель (Master Switch) и вытащить из `parsed_js/bundle.js` максимум интерактивных игровых хуков для полноценной игры через WebApp.

## 1. ЦЕЛЬ И БИЗНЕС-ТРЕБОВАНИЯ

1. **Главный ползунок (Master Kill-Switch):**
   - Добавить глобальный переключатель активности бота (`bot_enabled` / инвертированный `is_paused`) прямо в верхнюю закрепленную шапку (HUD), чтобы он был доступен с любого экрана.
   - При выключении главного ползунка все фоновые воркеры (`RoutineWorker`, `BossWorker`, `PrisonWorker`, `SocialWorker`) и `APScheduler` немедленно останавливают любые взаимодействия с игровым аккаунтом до повторного включения.
2. **Стабильный минимальный пинг и ускорение API:**
   - Устранить последовательные блокирующие вызовы к игровому серверу в `web/routes.py`, заменив их на параллельное выполнение через `asyncio.gather()`.
   - Настроить в `client/http_client.py` постоянный пул соединений `httpx.Limits(max_keepalive_connections=10, max_connections=20, keepalive_expiry=60.0)` и единый переиспользуемый `httpx.AsyncClient`.
   - Добавить быстрый эндпоинт `GET /api/v1/ping` (замер реального RTT до игрового API через легкий `GET /api/player/me` или `HEAD` + внутреннее время ответа) и кратковременное кэширование тяжелых каталогов (3-5 секунд), чтобы пинг в HUD был стабильным и низким (30-80 мс вместо 400-800 мс).
3. **Полноценный раздел «Ходки» (Дневной/Ночной режим, выбор тюрьмы, мгновенный слив энергии):**
   - Исправить переключение режима **День / Ночь** (`isDay=true` / `isDay=false`): при смене тумблера в UI немедленно сохранять `prison_prefer_night` в `BotConfig` и перезагружать состояние и чекпоинты выбранной тюрьмы для выбранной смены.
   - Добавить в раздел «Ходки» явный блок автопрохождения: выбор конкретной тюрьмы из списка всех тюрем (или "Авто - максимальная открытая"), переключатель смены (`День` / `Ночь`) и главный тумблер **«Автопрохождение ходок»** (`auto_prison`).
   - **Полностью убрать минимальный порог энергии (`prison_min_energy`):** если включено автопрохождение ходок (`auto_prison`) или авто-обучение у мастеров (`auto_masters`), бот обязан тратить энергию автоматически сразу, как только ее хватает хотя бы на 1 действие (`energy >= job_energy_cost`). Уменьшить базовый интервал проверки `PRISON_INTERVAL_MINUTES` до `3` минут и запускать проверку слива энергии сразу после сбора подогревов или туалетной бумаги.
4. **Исправление бизнесов (реальные уровни, свернутый вид, актуальная сумма прибыли):**
   - Исправить баг с отображением 1-го уровня: в ответе `GET /api/player/business/all` объединять справочник `businesses` с массивом `playerBusinesses` по ключу `businessId`, подставляя реальный `level` игрока.
   - В интерфейсе сделать список бизнесов **свернутым по умолчанию** (аккордеон с кнопкой разворачивания), а в видимой шапке карточки всегда отображать **точное количество ресурсов, которое будет получено при сборе прибыли** (суммарно по всем бизнесам с `level > 0` на основе `level * rewardPerLevel` и времени с `lastCollectTime`, сверив точную формулу начисления в `parsed_js/bundle.js`).
   - Обеспечить мгновенную актуализацию при открытии раздела или обновлении данных, а внутри развернутого списка добавить кнопку ручной прокачки уровня каждого бизнеса (если эндпоинт апгрейда бизнеса есть в `bundle.js`).
5. **Отдельный раздел «Кореша (Заявки в друзья)» с фильтрацией по статам:**
   - Вынести управление друзьями и заявками в отдельную вкладку меню **«Кореша»**.
   - Реализовать гибкие критерии автоматического приема заявок в `BotConfig`:
     - тумблер `auto_friends` (вкл/выкл автоприема);
     - режим `friend_accept_all` (принимать всех подряд или только по фильтрам);
     - минимальный уровень (`friend_min_level`), минимальный авторитет (`friend_min_authority`), минимальная бицуха (`friend_min_biceps`), минимальное кол-во талантов (`friend_min_talents`), минимальный урон ядом (`friend_min_poison_damage`), минимальный общий урон (`friend_min_total_damage`);
     - опция `friend_auto_decline_below` (отклонять не подходящих под фильтр или оставлять висеть).
   - Отображать в разделе «Кореша» актуальный список входящих заявок с характеристиками каждого игрока и кнопками ручного приема/отклонения.
6. **Максимальное извлечение игровых хуков из `parsed_js/bundle.js`:**
   - Просканировать `parsed_js/bundle.js` и подключить в API-клиенты и WebApp все доступные игровые действия, чтобы клиент полностью заменял вход в оригинальное приложение:
     - **Боссы:** призыв любого босса в выбранном режиме (`pacansky`, `blotnoy`, `avtoritetny`), сбор урона друзей (`GET /api/boss/friend-damage` / claim), покупка/активация баффов (`/api/boss-buffs/*`), покупка оружия у барыги при нехватке.
     - **Бизнесы и Прокачка:** улучшение уровня бизнеса, прокачка бицухи, распределение очков талантов (`/api/talent/*`).
     - **Нычки, Баулы и Коллекции:** открытие баулов (`/api/bauls/*`), экипировка/крафт шмота (`/api/stashgear/*`), обмен собранных коллекций (`/api/collection/*`).
     - **События и Двор:** бесплатные игры/вращения (колесо фортуны, кости, слоты, покер, кольщик за бумагу - строго при наличии бесплатных попыток/билетов), сбор наград ежемесячного календаря (`/api/monthly/*`), сходняки гильдии (`/api/shodnyak/*`).

## 3. ЛОГИКА / АРХИТЕКТУРА

2. Получения характеристик игроков из списка входящих заявок в друзья (`GET /api/friendship/requests` или дополнительный запрос профиля игрока по `userId`) и эндпоинта отклонения заявки (`decline-request`).
3. Эндпоинтов открытия баулов (`/api/bauls/*`), активации баффов босса (`/api/boss-buffs/*`), прокачки талантов (`/api/talent/*`), обмена коллекций (`/api/collection/*`) и бесплатных дворовых активностей.

### 3.2. Изменения в моделях и миграции (`core/models.py`, `core/database.py`)

   - `friend_accept_all` (Boolean, default `True`)
   - `friend_min_level` (Integer, default `0`)

   - `friend_min_biceps` (Integer, default `0`)
   - `friend_min_talents` (Integer, default `0`)

В `core/database.py` внутри `init_db()` добавить проверку существующих колонок `bot_configs` через `PRAGMA table_info(bot_configs)` и автоматический `ALTER TABLE bot_configs ADD COLUMN ...` для новых полей, чтобы существующая база `storage/prison_bot.db` обновилась без потери данных и без необходимости ее удалять.

### 3.3. Оптимизация сети и пинга (`client/http_client.py`, `web/routes.py`)
1. В `GameHttpClient`:
   - Использовать единый экземпляр `httpx.AsyncClient` с `limits=httpx.Limits(max_keepalive_connections=10, max_connections=20, keepalive_expiry=60.0)` и `timeout=httpx.Timeout(10.0, connect=3.0)`.
2. В `web/routes.py`:
   - Добавить `GET /api/v1/ping`: выполняет быстрый запрос `GET /api/player/me` к игровому серверу (с кэшем на 2 секунды при частых опросах) и возвращает `{"ok": true, "game_ping_ms": <int>, "server_ts": <float>}`.
   - В `GET /api/v1/live/profile`, `GET /api/v1/live/boss`, `GET /api/v1/live/prisons` запускать независимые запросы к игровому API строго параллельно через `asyncio.gather(...)`.
   - В `GET /api/v1/live/profile` формировать список бизнесов путем сопоставления `businesses` и `playerBusinesses` по `businessId`, возвращая для каждого купленного бизнеса (`level > 0`): `businessId`, `prisonId`, `title`, `level`, `maxLevel`, `rewardType`, `rewardPerLevel`, стоимость следующего апгрейда и суммарный объект `pendingResources` (точное количество ресурсов к получению прямо сейчас).

### 3.4. Логика `PrisonWorker` и `SocialWorker`
1. **`PrisonWorker` (`workers/prison_worker.py`):**
   - Удалить проверку `current_energy < min_energy`.
   - Определять стоимость энергии следующей доступной ходки из чекпоинтов выбранной тюрьмы и выбранной смены (`is_day = not config.prison_prefer_night`).
   - Если `config.auto_prison` включен и `current_energy >= job_energy_cost` - выполнять цикл ходок `while current_energy >= job_energy_cost` до полного расхода доступной энергии.
   - Если `config.auto_masters` включен и осталась энергия, достаточная для тренировки у `config.master_target_id` - автоматически выполнять `do_master_work(master_id)`.
2. **`SocialWorker` (`workers/social_worker.py`):**
   - При включенном `config.auto_friends` загружать входящие заявки `get_friend_requests()`.
   - Если `config.friend_accept_all == True` - принимать все заявки.
   - Если `config.friend_accept_all == False` - для каждой заявки проверять соответствие всем заданным порогам (`level >= friend_min_level`, `authority >= friend_min_authority`, `biceps >= friend_min_biceps`, `talents >= friend_min_talents`, `poisonDamage >= friend_min_poison_damage`, `totalDamage >= friend_min_total_damage`). Подходящих принимать (`accept_friend`), неподходящих отклонять при `friend_auto_decline_below == True` или пропускать.
