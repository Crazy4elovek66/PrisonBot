## 1. Архитектура раздела «Рейды и Новости» в `@pro_prison_bot`

### 1.1. Клиентские компоненты и логика
В `@pro_prison_bot` функционал раздела «Новости и Рейды» реализован в чанках `39aopsuqaj4w-.js` и `3j44qqt8acear.js`.
Интерфейс представляет собой сегментный переключатель двух подвкладок:
- **`Рейды`** (`value: "raids"`): список активных и предстоящих бригадных рейдов;
- **`Новости`** (`value: "news"`): официальные объявления разработчиков и рекламные посты игроков.

### 1.2. Эндпоинты бэкенда ProPrisonBot
- `GET /api/raids` — список доступных рейдов;
- `GET /api/raids/:id/claims` — детальный список участников рейда с заявленным и реальным уроном;
- `POST /api/raids/mark-read` — отметка прочитанных рейдов;
- `GET /api/news?limit=N` — лента новостей;
- `GET /api/news-ads` — рекламные посты игроков и кланов;
- `POST /api/brigade/fae-members` — проверка участников бригады по списку `gameUserIds`.

Каждая заявка участника (`claim`) в `ee.claims` содержит:
- `gameUserId`: уникальный цифровой ID игрока в «Тюряге» (например, `9000000000141538`);
- `nickname`: игровой никнейм;
- `claimedDamage`: заявленный урон;
- `actualDamage`: фактически нанесенный урон;
- `isFriend`: статус дружбы (вычисляется на клиенте через `!ea.isFriend(e.gameUserId)`).

## 3. Анализ игрового API «Тюряга» (`parsed_js/bundle.js`)

Поскольку рейды ProPrisonBot закрыты серверным paywall для бесплатных пользователей, в игровом клиенте `oldprison-prod.luckygem.online` (`parsed_js/bundle.js`) были найдены прямые официальные источники активных игроков и точный контракт отправки заявок в друзья.

### 3.1. Контракт отправки заявки в друзья (Friendship API)
В `bundle.js` (Module 415, строки 100228–100237 и строки 154068–154090):
- **Маршрут:** `POST /api/friendship/send-request?toUserId={targetUserId}`
- **Заголовки:** `Authorization: Bearer <game_token>`, `Content-Type: application/json`
- **Тело запроса:** Пустое (`{}` или `null`)
- **Успешный ответ:** `{"success": true}` (или HTTP 200/204)
- **Коды/сообщения ошибок:**
  - `Нельзя добавить самого себя` (проверяется клиентом `if (targetUserId === myUserId)`);
  - `Заявка уже отправлена` / `Вы уже друзья`;
  - `Достигнут лимит друзей` (`friends_limit_reached`);
  - `Слишком много запросов` (HTTP 429 при флуде без задержки).

### 3.2. Официальные источники активных дамагеров из игры
1. **Еженедельный топ урона (`Ce.Q.WEEKLY_TOP.GET_TOP(100)`):**
   - **Маршрут:** `GET /api/weekly-top/top?limit=100`
   - **Формат данных:** массив `top: [{ userId, nickname, damage, rank, ... }]`, `nextResetLocal`
   - **Ценность:** 100 самых активных игроков игры, нанесших максимальный урон по боссам за текущую неделю.
2. **Топ достижений (`Ce.Q.WEEKLY_TOP.GET_ACHIEVEMENTS(100)`):**
   - **Маршрут:** `GET /api/weekly-top/achievements?limit=100`
3. **Составы топовых бригад (`Ce.Q.GUILD.GET_MEMBERS(guildId)`):**
   - **Маршрут:** `GET /api/guild/{guildId}/members`
   - Позволяет выгрузить полные списки участников сильнейших кланов Тюряги.
4. **Объявления о наборе (`Ce.Q.GUILD.RECRUITMENT.GET_LIST(100)`):**
   - **Маршрут:** `GET /api/guild/recruitment/list?limit=100`

## 4. Инженерная стратегия для `PrisonBot`

1. **Вкладка «Новости»:**
   - Подключается к прямому источнику `/api/news` ProPrisonBot (работает через активный сессионный токен бота с кэшированием 60 секунд).
2. **Вкладка «Рейды»:**
   - Честно сообщает статус: `ProPrisonBot API: Требуется активная платная подписка (403 SUBSCRIPTION_REQUIRED)`.
   - При наличии подписки — автоматически отображает официальные рейды ProPrisonBot.
   - При paywall — активирует два мощных альтернативных источника:
     1. **«Игровой радар дамагеров»:** запрашивает живой топ урона `GET /api/weekly-top/top?limit=100`, фильтрует текущего игрока, текущих друзей и уже отправленные заявки, позволяя добавлять сильнейших игроков игры в 1 клик или пачкой.
     2. **«Импорт текста рейда»:** поле быстрой вставки скопированного текста из Telegram-чата рейда бригады. Парсер извлекает 64-битные `gameUserId`, заявленный урон и имена, обогащает профили и выводит готовую карточку с кнопками добавления.
3. **Безопасная пакетная отправка заявок:**
   - Очередь с человекоподобной задержкой (`1.5 – 3.0 сек`), остановкой при лимите друзей и сохранением в БД `SentFriendRequest` для исключения дубликатов.

### 5.2. Официальные эндпоинты гильдий (бригад) игры «Тюряга» (`parsed_js/bundle.js`)
В оригинальном клиенте игры (`oldprison-prod.luckygem.online`) подтверждена структура API гильдий:
1. `GET /api/guild/recruitment/list?limit=100` (`GUILD.RECRUITMENT.GET_LIST`) — возвращает перечень открытых и набирающих бригад с полями `guildId`, `name`, `membersCount` и др.
2. `GET /api/guild/{guildId}/members` (`GUILD.GET_MEMBERS`) — возвращает массив участников бригады:
   - `userId` (целое число / 64-битный ID);
   - `nickname` / `nicknameFull` (ник игрока);
   - `role` (роль: лидер, офицер, боец);
   - `rankId`, `rankName` (ранг в бригаде);
   - `activityRating` / `bossDamage` (активность или нанесенный урон по боссам);
   - `campActivity` (статус активности в лагере);
3. `GET /api/weekly-top/top?limit=100` — еженедельный топ урона;
4. `GET /api/weekly-top/achievements?limit=100` — топ достижений.

### 5.3. Карта лимитов и Circuit Breaker (Anti-Ban Guard)
1. **Игровой сервер «Тюряга»:**
   - Суточный лимит исходящих заявок в друзья: по умолчанию `25` в 24 часа (программный потолок `<= 50`);
   - Ошибка `429 Too Many Requests` -> немедленный Circuit Breaker на `60 минут` (3600 сек);
   - Ответ `friends_limit_reached` (лимит друзей аккаунта) -> Circuit Breaker на `24 часа` (86400 сек);
   - 3 подряд ошибки `4xx/5xx` -> остановка текущего цикла;
   - Сканирование бригад: максимум `8` бригад за один проход с задержкой (jitter) `1.5..3.0 сек`, cooldown ручного вызова `300 сек` (5 минут).
2. **Telegram (Telethon):**
   - Строго Read-Only доступ к последним 15 сообщениям указанных публичных каналов;
   - Серверный cooldown опроса каналов: `900 сек` (15 минут);
   - При `FloodWaitError as e`: немедленная пауза сканера на `e.seconds + 60` секунд.
