### 1.2. Режимы боя и точные множители HP
Из декомпилированного модуля 733635 Next.js клиента:
```javascript
let t = {
  pacansky: 1,
  blotnoy: 3,
  avtoritetny: 6,
  vorovskoy: 12,
  odin: 1,
  brigade: 1
};
function getBossHp(boss, mode) {
  let mult = t[mode] || 1;
  return boss.baseHp * mult;
}
```
Каждый босс содержит в `battleModes` только разрешенные для него режимы:
- Если режим отсутствует в `battleModes` (например, у Кирпича и Тротила нет `blotnoy` и `avtoritetny`), кнопка режима блокируется или скрывается.
- При переключении режима в интерфейсе значение HP мгновенно пересчитывается: `baseHp * mult`.

### 2.4. Позиционирование кисти (`BrushAnim` / Zone 6)
Смещение кисти берется строго из таблицы `f.X[r] ?? f.b`:
- `f.b = { x: -241, y: -382, scale: 1.183 }`
- По умолчанию кисть руки отрисовывается на плече/предплечье, а не в области шорт.
- При анимации по JSON-атласу (моргание `EyesAnim`, движение руки `BrushAnim`) кадр выбирается через функцию:
  ```javascript
  function getSequenceFrame(atlas, timeMs) {
    if (!atlas.sequence || atlas.sequence.length === 0) return atlas.frames.values().next().value;
    const totalDuration = atlas.sequence.reduce((acc, f) => acc + f.delay, 0);
    let rem = timeMs % totalDuration;
    for (const step of atlas.sequence) {
      if (rem < step.delay) return atlas.frames.get(step.frame);
      rem -= step.delay;
    }
    return atlas.frames.values().next().value;
  }
  ```

## 5. Контракт Режима «В одного» («odin») и Блокировки Боссов

### 5.1. Режим «В одного»
- Ключ режима в игре: `"odin"` (в коде `t = { pacansky: 1, blotnoy: 3, avtoritetny: 6, vorovskoy: 12, odin: 1, brigade: 1 }`).
- Иконка режима: `/assets/PrisonV3/bosses/Icon/icon_Solo.png` (локально: `web/static/assets/icons/icon_Solo.png`).
- Множитель HP: 1 (`baseHp * 1`).
- Запуск боя: `POST /api/boss/start-attack` с телом `{"bossId": <id>, "mode": "odin"}`.
- Награды: уникальный набор валют, дропа и шанса выпадения частей сетов и хат для соло-битвы.

### 5.2. Правила блокировки боссов (`isLocked`, `unlockReason`)
- Боссы могут быть временно или постоянно заблокированы:
  1. `unavailableReason === "prison_runs_required"` или `access.available === false`: требуется определенное количество дневных ходок или ночных бунтов в конкретной тюрьме (функция `xS(t)` формирует строку вида: `Нужно 5 дневных ходок в Бутырке, пройдено 0`).
  2. Ивентовые / временные боссы (например, `Тротил` id=56, `Гастролёр` id=19, `Конвой` id=20): босс заблокирован, если не наступило окно доступности (`arrivals[bossId].isOpen === false` или таймер обратного отсчета).
  3. Требование победы над предыдущим боссом: если в `unlockRequirement` указан `requiredBossId` и `wins[requiredBossId] == 0`, то `isLocked: true`, `unlockReason: "Победите босса «<Имя>»"`.
- Для заблокированных боссов карточка визуально затемняется (`opacity: 0.55`, бейдж `🔒 Закрыт`), отображается плашка с `unlockReason`, а кнопки атаки деактивируются. `BossWorker` в цикле авто-призыва пропускает боссов с `isLocked === true`.

В `PlayerSprite` и `PlayerSpriteBack` игры:
- **Передние зоны (отображаются в обычной Примерочной):**

## 9. Контракт Живой Проверки Доступности Бригадных Усилений

### 9.1. Данные гильдии (`GET /api/guild/status`)
- Поле `inGuild: bool`:
  - если `false` или `guild is None` -> все бригадные баффы имеют `isLocked: true`, `canActivate: false`, `unlockReason: "Вы не состоите в бригаде"`.
- Поле `guild.level`:
  - `Навались` (`guild_buff_poison`): требуется `level >= 50`. Если меньше: `unlockReason: f"Нужен уровень бригады 50 (сейчас {guild.level})"`.
  - `Смотри не разбей` (`guild_buff_gunshot`): требуется `level >= 40`. Если меньше: `unlockReason: f"Нужен уровень бригады 40 (сейчас {guild.level})"`.
- Поле `myRank.rankId` и `myPrivileges`:
  - для активации бригадного баффа требуются полномочия `activateGuildBuff` (или ранг 1..3). Если полномочий нет: `canActivate: false`, `unlockReason: f"Требуются полномочия в бригаде (ваш ранг: {myRank.name})"`.

### 9.2. Баффы Сходняка (`GET /api/shodnyak/buffs`)
- Сопоставляются с рангом бригады в Сходняке 1..20.
- Не открытые по результатам Сходняка баффы получают `isLocked: true`, `canActivate: false`, `unlockReason: "Закрыто (требуется N место в Сходняке)"`.
- Активные получают `isActive: true` с таймером окончания.
- Находящиеся на перезарядке получают `cooldownEndsAt` с таймером отката.

## 10. Контракт Максимального Ускорения Ассетов и Примерочной

### 10.1. Высокопроизводительный Бэкенд-Прокси (`web/routes.py`)
- **HTTP/2 Connection Pooling:** переиспользуемый клиент `httpx.AsyncClient(http2=True, limits=httpx.Limits(max_connections=60, max_keepalive_connections=30, keepalive_expiry=120.0))`. Исключает затраты на повторные TCP/TLS рукопожатия с CDN игры.
- **In-Memory RAM LRU-кэш:** быстрый кэш `_ASSET_LRU_CACHE` (`OrderedDict`, до 500 элементов) поверх дискового хранилища `storage/asset_cache/`. Повторная отдача ассетов происходит за `< 0.1 мс` без дискового I/O.
- **Пакетная выгрузка (`POST /api/v1/assets/batch`):** принимает до 50 путей, параллельно с семафором 20 читает кэш и докачивает отсутствующие файлы с CDN по HTTP/2, возвращая Base64 Data URLs за 1 единственный HTTP-запрос. Обходит браузерный лимит в 6 одновременных соединений по HTTP/1.1 к `127.0.0.1:8080`.

### 10.2. Оптимизация Фронтенда (`web/static/app.js`)
- **Offscreen Static Canvas Compositing:**
  - Создан offscreen буфер `fittingRoomStaticCanvas` размером `1510 x 1124` (retina DPR=2).
  - Все статические слои (фон хаты, базовое тело, татуировки, статическая одежда) отрисовываются в offscreen буфер **ровно один раз** при изменении набора слоев.
  - В цикле `requestAnimationFrame` выполняется всего 1 вызов `ctx.drawImage(fittingRoomStaticCanvas, 0, 0, 755, 562)` + поверх отрисовываются только живые анимации (`EyesAnim`, `BrushAnim`).
  - При отсутствии анимаций (вид со спины или статический образ) цикл `requestAnimationFrame` автоматически останавливается, исключая 60 FPS нагрузку на GPU/CPU.
- **Раздельная загрузка по сторонам (Split Loading):**
  - При открытии Примерочной загружаются только слои активной стороны (`front` или `back`).
  - Слои противоположной стороны тихо предпрогреваются в фоне сразу после первого кадра.
- **Browser Cache API & Hover Prefetch:**
  - Клиентский кэш `caches.open("prison-assets-v1")` сохраняет загруженные спрайты между перезагрузками страницы.
  - По `pointerenter` с debounce 120 мс на карточках сетов (`.wardrobe-set-card`) и чипах лута боссов (`.boss-loot-item-chip`) запускается фоновый прогрев ассетов.
